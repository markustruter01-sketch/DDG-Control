DDG Control workspace. Development preview and development database only. Do not publish.

GOAL
Make the login lockout work correctly when published: store failed attempts in the database, lock one address after 5 failures in 15 minutes, and lock login for everyone after 20 failures from all addresses combined in 15 minutes.

DONE WHEN
- 5 wrong passwords from one address make its 6th attempt return 429, while a different address still gets 401.
- Once failures from all addresses total 20 within 15 minutes, any login attempt from any address, including one with the correct password, returns 429.
- After test cleanup, the correct password returns 200.
- Failed attempts live in a database table, not in memory.
- `pnpm run typecheck` passes.

   - id: serial primary key

   - created_at: timestamp, not null, default now
   Add an index on created_at. Export it from lib/db/src/schema/index.ts.

3. In auth.ts, replace the in-memory failure counter with the failed_logins table:
   a) Before checking the password, count rows from the last 15 minutes:

      - Else if rows for this address total 5 or more, return 429 {"error":"too many attempts"}.
   b) On a wrong password, insert one row for this address. Do not insert a row for 429 responses.

   d) On every wrong-password insert, also delete rows older than 1 day.
